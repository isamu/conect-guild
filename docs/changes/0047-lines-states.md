# #47 メンバーがセリフを言う（2026-10-12）

2 本目（状態の変わり目の一言）。

- 承認まち・確認まち・許可待ちの記号の吹き出しが新しく出た人が、ときどき（確率 0.3、`LINES.remarkChance`）一言言うようにした（4.12）。言うのは 2.0 秒で、そのあとは記号に戻る。社長の判断（「たまに」でよい、ふだんは記号のまま）を受けて、確率と時間は定数にした
  - 判定は `render/remarks.ts` の純粋関数（前回と今回の記号の比較、言える人、確率、続けて言う順）で、時刻・乱数・言える人を引数で受ける。セリフの選び方と乱数の源は 1 本目と同じ（`lines.createLinePicker`、`lineRandom`）
  - 比べるのは Canvas に渡る party の記号。最初の snapshot の前の空の party と比べないように、Canvas に「snapshot から作った party か」を渡すことにした（`StageParty.known`。実装時の判断）
  - かなめは PR の確認（「…」）と許可待ち（「?」）で言う。設計案の「PR の確認（かなめ側）」をかなめの確認まちの場面として入れ、かなめの文を足した（実装時の判断）
  - 確認まちから承認まちのように別の記号に変わった人も言う。同じ記号が続く間は、言わなかった人も次の取得で言わない
  - 同じ取得の複数の人は、設計案の「0.6 秒ずらす」ではなく、前の人が言い終わってから次の人が言うことにした。席が近い人どうしの吹き出しが重なるため（実装時の判断）
  - 演出の途中・遊びに出ている・席へ帰る途中の人は言わない。遊びの姿勢は暇の記録から副作用なしで引けるように `IdleCrew.poses()` を足した（`frame()` は演出中の人を「動いた」と知らせ、それが party をまた渡すので、party を受けるときには使えない）
  - 頭上の優先順位に、出来事の一言と待ちの記号の間の段として入れた。記号と同じく席で待つ印なので、演出の間は隠れる
  - 直近に数えるのは画面に出た一言だけにした（1 本目の仕組みに合わせた。呼びかけの言葉や出来事の一言に隠れていたもの、演出の間に隠れていたものは数えない。`remarks.seenRemarks`）。一言の場面を `lineBook` の `sceneOfLine` が引けるようにした
  - レベルアップ（4.6）は紙吹雪と「LEVEL UP」の文字が出ている間も演出なので、一言は隠れ、新しくも言わない。文字と重ならないことを vitest で確かめた（codex レビューで重なりを指摘されたが、演出の間は一言が隠れるので起きないことをテストで示した）
- スクリーンショットで、ささえの「いいかしら？」が右の列の窓の下に隠れていたので、右に出すと窓にかかる言葉の吹き出しを頭の左上に出すことにした。1 本目のささえの出来事のセリフも同じだったので、この修正は 1 本目の PR に移した（4.12 の「重なり」）
