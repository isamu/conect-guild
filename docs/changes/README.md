# 変更履歴の置き方

設計書（`docs/DESIGN.md`）を変えた経緯を、Issue ごとのファイルに分けて置く。並行して進む PR が同じファイルの同じ位置に追記して衝突しないようにするため（Issue #54）。

- **1 Issue 1 ファイル。** Issue の最初の PR で、その Issue のファイルを新しく足す。ほかの Issue のファイルには触れず、既に書いた項目も書き換えない
- **ファイル名**: `<Issue 番号 4 桁>-<英小文字・数字・ハイフンの短い名前>.md`（例: `0028-king-summons.md`）
- **Issue の無い変更**: `pr-<PR 番号 4 桁>-<短い名前>.md`（例: `pr-0031-toy-poodle.md`）。PR も無いときは `<日付>-<短い名前>.md`（例: `2026-10-12-foo.md`）。短い名前はどれも英小文字・数字・ハイフンだけにする
- **見出し**: `# #<Issue 番号> <Issue の題>（<日付>）`。Issue の無い変更は `# PR #<番号> <PR の題>（<日付>）`、PR も無いときは `# <題>（<日付>）`
- **本文**: 箇条書きで、何を変えたか・なぜそうしたか（社長の判断、レビューの指摘、実装時の判断）と、関係する DESIGN.md の章を書く。仕様そのものは DESIGN.md に書き、ここは経緯だけにする
- **同じ Issue を複数の PR で進めた場合**: 2 本目以降の PR は、その Issue のファイルの末尾に項目を足すだけにする（古い順に並ぶ）

Issue #54 より前の分は、DESIGN.md の「変更履歴」の節から文言を変えずに移した。段階（M1〜M4）の項目は、その段階の Issue（M1 は #5、M2 は #8、M3 は #13、M4 は #19）のファイルに入れた。1 つの PR で複数の Issue を扱った項目は、分けずに主な Issue のファイルに入れた（「M4 の一部」は PR #22 で #19 の昼夜と #11 の小物の動きを扱ったため、#19 のファイルにある）。これからは、1 つの PR が複数の Issue を扱うときも、主な Issue のファイルに書き、ほかの Issue の番号を本文に書く
