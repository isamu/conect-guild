# #49 動画撮影用のデモモード（2026-10-12）

- `?demo=1` で、架空のクエストの台本を効果音つきでくり返し再生するデモモードを足した（DESIGN.md 3 章、4.11、9 章）。社長の依頼（X と note の動画）
  - デモ中は `/snapshot.json` を読まず、localStorage にも書かない。差分の基準・音の設定・暇の時刻はメモリに置く。デモの音の設定は最初から「音を出す」にし、ふだんの音の設定は書き換えない（実装時の判断）
  - 台本は「出来事の列」（`domain/demoScript.ts`）にし、時刻 → 架空の snapshot の純粋関数（`domain/demo.ts`）で既存の差分・演出・効果音・ナレーションにそのまま流す。#19 の Lv 表示や #47 のセリフが入ったら、行を足して台本に加える
  - 1 周 60 秒に 4 部門すべての巻物・宝箱・クリアを入れると、メッセージ 12 件の最短の時間（8 秒ずつ）だけで約 100 秒かかる。1 周に 2 部門ずつにし、周ごとに組を入れ替えた（2 周で 4 部門。実装時の判断）
  - 台本の頭に王様の指示（#28。かなめのセッションが待機 → 作業中で、王様が呼びかけ、かなめが「はっ！」）を入れた。部門が作業を始めるときも同じく王様が呼びかける（1 周に 4 回）
  - 「はじめる」の窓を出し、そのクリックで音を有効にする。Canvas の絵の読み込みが終わるまでと、Canvas が隠れる狭い画面では押せない（その間の王様の呼びかけは捨てられ、台本の頭の呼びかけと音が欠けていた。統合レビューの指摘）。Canvas を始められなかったときも準備完了を知らせ、演出の合図をためない（codex レビューの指摘。判定を app/stageBoot.ts の純粋関数に切り出してテストした）。取得の窓は「基準を消す」の代わりに「デモ（架空のデータ）」と出す
- 撮った動画に音が入らなかった原因を調べ、README に「撮影のやり方」を書いた。macOS の標準の画面収録（Cmd+Shift+5、QuickTime Player）はマイクしか録れず、ブラウザの音は入らない。アプリの側は、はじめるを押すと AudioContext が running になり効果音が鳴ることを確かめた（E2E と、本物の Chromium で手元で確認）
- #19 の Lv の表示が main に入ったので取り込み、デモの架空の history から Lv が出ることを確かめた（vitest と E2E、見た目）
- README の撮影手順を「先に録画を始めてから、はじめるを押す（冒頭は編集で切る）」に直した。押してから録ると、0.5 秒後の最初の王様の呼びかけを撮り逃すため（統合レビューの指摘）
