# #47 メンバーがセリフを言う（2026-10-12）

1 本目（出来事の一言）。

- メンバーが出来事の決まった瞬間に、短いセリフを Canvas の吹き出しで言うようにした（4.12、3 章）。巻物を手渡す・投げる・受付で受け取る、宝箱を届ける・受け取る、クリア（王様はクリアのときだけ反応）。状態の変わり目の一言とつぶやきは 2 本目・3 本目
  - セリフはコードにメンバー ID ごと・場面ごとに置いた固定の文だけで、ひらがな・カタカナ、最大 7 文字。会社の実際の話に読める文（「くろじです！」「バズった！」に加え、「あいました！」「ごうけい、よし」「しめました！」）は外した（社長の判断を受けて実装時に判断）
  - 部門なしのクリアはかなめが言うので、設計案に無かったかなめのクリアの文を足した（実装時の判断）
  - 頭上に出すものを優先順位の純粋関数（`render/overhead.ts`）に切り出した。#28 では draw.ts の if で決めていた
  - 投げたときは巻物が 0.9 秒で届くので、担当はかなめの 1.2 秒が終わってから言う（ふたりの吹き出しを重ねないため。実装時の判断）
  - 掲げた宝箱が吹き出しの左端の下に入っていた（スクリーンショットで確認）。物は頭の真上の中央にあり横で重なるため、数 px ではなく、掲げている間だけ 36px 上げて物の上に出すことにした（実装時の判断）
  - 巻物を投げる演出（#12）にセリフを付けるため、ブランチに main を取り込んだ
  - Lv のタグ（#19 の 2 本目）を取り込んだところ、ひらめの席のセリフ（5 文字以上）がカウンターのかなめのタグに、かなめの 7 文字のセリフがひびきの机のタグにかかった（vitest で全台本を調べて分かった）。言葉の吹き出しがタグにかかるときだけ、タグの 2px 上まで上げることにした（司令塔の指示を受けた実装時の判断。タグの位置は変えない）
  - codex レビューの指摘で、ループの組み立て（`sceneContext`）でセリフを選んでも紙吹雪と投げる判定の乱数の列が変わらないことを確かめるテストを足した
  - codex レビューの指摘で、halted の間に演出が始まってもセリフを選ばないようにした（それまでは halted に入った時点のセリフだけを捨てていた）。タグの上へ上げた吹き出しがさらに上のタグにかかるときは、そのタグの上まで続けて上げるようにした（いまの席の並びでは起きない）
  - 同じく、狭い画面で Canvas が隠れていて捨てる演出でもセリフを選ばないようにした。選ぶと、見えなかったセリフが「直近に言った」扱いになるため
  - 同じく、直近のセリフを、選んだ時点ではなく画面に出た時点で覚えるようにした。選んだ時点で覚えると、捨てたり呼びかけに隠れたりして出なかったセリフまで「直近」に数えるため。まだ出ていない予定のセリフは選ばない
  - 同じく、呼びかけに一時隠れてまた出たセリフを 2 回覚えないよう、発話（メンバーと始まりの時刻）ごとに 1 回だけ覚えるようにした。候補がすべて出る予定のときは、同じセリフを重ねて予約せず何も言わない
  - デモモード（#49）を取り込み、デモの台本でもセリフが演出と一緒に出ることを E2E で確かめた（最初の巻物でかなめとみのりが言う）。デモは描画の乱数を注入しないので、セリフの乱数（本番の既定の `Math.random`）とぶつからない。デモの節が 4.11 になったので、セリフの節は 4.12 にした
  - 2 本目の作業で、ささえの席から右に出す 4 文字以上の吹き出しが右のパーティの窓の下に隠れることが分かった（1 本目の takeScroll・clear のセリフも該当）。2 本目の直し（右に出すと窓にかかる言葉の吹き出しは頭の左上に出す。どのセリフも窓にかからないテスト）を cherry-pick で取り込んだ（司令塔の指示）
